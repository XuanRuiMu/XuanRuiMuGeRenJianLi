## 一、摘要结论

### 1.1 核心判断

**他的能力结构与 2026 年招聘市场的结构性变化高度匹配，但当前简历定位完全错位。**

- **市场端**：2026 年 AI 岗位数量同比暴涨约 12 倍（脉脉），AI 智能体相关职位数同比增速高达 455%（智联），AI 岗位占新经济岗位比例从 2.29% 升至 26.23%。但 AI 岗位 71% 要求本科及以上、79% 要求工作经验，算法层 54%+ 要硕士——**应用层/落地层岗位本科可投，算法层/研究层岗位硕士为主**，这一结构性分野是他的机会窗口。
- **能力端**：他的 85+ 自定义 Skill、多 Agent 编排、MCP、独立交付上线全栈产品的经历，恰好对应市场增量最大的"用机器干活的人"（AI 应用/业务流程改造）岗位族。2026 年越来越多公司在面试中允许甚至要求使用 AI 编码工具，考的是"驾驭 AI 的能力"而非手写代码——这正是他的主场。
- **定位端**：当前简历求职方向写"Java 后端/全栈/AI 工具开发"，RoleTicker 为['全栈开发工程师','Java 后端开发','AI 工具开发','游戏服务端架构','DevOps 工程师']——**完全没有对齐 AI Agent 应用主航道，也未覆盖低代码/RPA/实施等相邻岗位**，等于拿着最强的武器去打最不擅长的战场。

## 四、片C：面试与简历策略

### 4.1 目标岗位的面试流程与考察重点

**各岗位族面试对他的适配度**

| 岗位族 | 是否考手撕代码/算法 | 核心考察 | 对他适配度 |
|---|---|---|---|
| AI 应用工程师（大厂） | 是，coding+系统设计 | LLM 概念、RAG、推理优化、coding | **低**——大厂仍卡算法 |
| AI 应用工程师（中小厂/创业公司） | 部分，可能允许用 AI | 项目实操、Agent 编排、落地能力 | **高**——他的主场 |
| RPA 实施/开发 | 否，但有 RPA 工具实操机考 | 工具熟练度、异常处理、业务流程理解、沟通 | **高** |
| 低代码开发/实施 | 否 | 平台操作、需求调研、业务理解 | **高** |
| 软件实施 | 否，只考简单 SQL/Linux | 沟通、客户培训、问题排查、文档 | **高**——B 站授课/一对一指导经验直接加分 |
| 技术支持/IT 运维 | 否 | Linux 基础、故障排查、沟通 | **高**——190+ 插件 Purpur 运维经验 |
| AI 训练师/AIGC 运营 | 否 | 标注规则、Prompt、数据质量判断 | **中**——入门门槛低但天花板低 |
| vibe coding 前端 | 新题型：考 AI 驾驭能力 | prompt 质量、AI 代码审查、trade-off 解释 | **高**——但纯 vibe coding 岗位名仍较少 |

**关键面试趋势**：2026 年越来越多公司允许甚至要求面试中使用 AI 编码工具，考的是"你如何驾驭 AI"而非"你手写多少代码"。考察点变成：prompt 质量、AI 产出代码的审查与纠错能力、迭代效率、对 AI 生成代码的安全/质量把关。

**RPA 面试**：典型 3-4 轮——技术筛（UiPath 基础概念/selector/工作流）→ 进阶技术（ReFramework、异常处理、Orchestrator）→ 实操机考（live automation challenge、debug 现有流程）→ HR 面。不考手撕算法。

**软件实施面试**（以泛微为例）：笔试只考简单 Linux+SQL，不考算法；一面 HR 问动机/对实施岗的理解；二面问 MySQL 多表查询、左右连接区别、Linux 常见命令、Postman、JSON。

**AI 训练师面试**：不考编程，核心考标注规则制定能力（标注前定规则→培训标注员→双人标注交叉验证→标注后分类统计）、数据质量判断（安全一票否决→指令遵循→内容质量→语言表达四维度）。

### 4.2 如何展示"用 Agent 独立交付上线产品"的能力

**核心原则**：不要假装没用 AI，也不要过度坦白成"我只按了按钮"。主流建议是：Lead with 问题本身，把 AI 工具放在合适位置（"用 AI 作为加速器"），明确区分"AI 协助了什么"和"你自己做了什么决策/集成/验证"。

**官方口径（上海人社局）**：严禁借助 AI 虚构工作/实习/项目经历或夸大成果；所有履历描述须基于真实情况，明确标注自己在经历中的具体角色与实际贡献。

**被问"这是你自己写的吗"的标准答法**：坦诚+聚焦 ownership。"我使用 Claude Code/Codex 作为开发加速器，负责需求拆解、架构决策、集成联调、部署上线和问题排查，AI 负责代码补全和样板代码生成。"

**把技术术语翻译成面试官语言**

| 他的技术术语 | 面试官听得懂的表述 |
|---|---|
| 85+ 自定义 Skill | "沉淀了 85+ 个可复用的 AI 工作流模板/自动化脚本，把重复性开发任务标准化" |
| 多 Agent 编排 | "设计并实现多智能体协作流程，让不同专职 AI 角色分工完成复杂任务链，类似一个 AI 开发团队的项目经理" |
| MCP | "熟悉 Model Context Protocol，能让 AI 安全地调用外部工具和数据源" |
| Hooks/Rules | "建立了 AI 编码的规范约束体系，确保 AI 生成代码符合项目规范、安全要求和测试标准" |
| 开源"循环工程"编排 Skill | "开源了一套 AI Agent 编排框架，在社区有真实用户" |

**作品集展示策略与权重**：在线 Demo > GitHub README > B 站演示视频 > 简历网站本身（按"面试官点击成本从低到高"排序）。Live demo 链接是最高信号元素。真实用户是最强证据——他的 200 人 QQ 学习群、Minecraft 服务器 2019 年至今长期运维，都是"有真实用户"的硬证据，必须写进简历。

### 4.3 作品集与 GitHub 在目标岗位招聘中的权重

- **低代码/RPA 实施岗**：GitHub 权重低，证书+项目经验+沟通能力更重要。有 1-2 个 RPA/低代码实操 demo 视频+对应厂商认证比 GitHub 更有效。
- **AI 应用/Agent 开发岗**：GitHub 和作品集权重高。2026 校招趋势是"AI 岗位重项目、轻学历、轻实习"——成型的 RAG/智能体项目比空洞的实习经历更有说服力。
- **软件实施/技术支持岗**：作品集权重最低，沟通+SQL/Linux 基础+行业理解更重要。
- **三本学历候选人**：作品集能部分弥补但不能完全替代学历。
