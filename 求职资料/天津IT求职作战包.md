**三条纪律**：
1. **同一故事换题型只改"结果"那句话的落点，事实部分一字不改。**
2. **故事 4 只能证明"接受反馈"，不能证明"团队协作"**——别讲过头，被追问"那你们几个人"就塌。
3. **故事 8 是新增的，也是你最被低估的一条**：它是唯一证明"真实世界发生了意外、你兜住了"的证据，过去一直被埋在"三级降级"这个技术名词下面。

### D-2｜两个关键故事的口语版（可直接背）

**故事 4（协作类，约 60 秒）** —— 你"无实习"短板的最优替代证据
> 我运维一个多插件服务端集群的数据层，两年多了，玩家权限和经济数据都在 MySQL 里。这个场景跟自己写项目最大的区别是：需求不是我定的——服主要加功能，插件作者升版本可能改表结构，玩家数据出问题会立刻来找你。所以我养成了两个习惯：一是备份之后一定做恢复校验，没验证过的备份等于没备份；二是跨服迁移先跑影子环境再切，出问题先恢复服务再定位原因，不在生产上考古。这段经历跟企业的差别是流程规范，不是责任。

- **落点句**：「这是我真实被别人依赖、被别人催、需求会变、出错要背锅的场景——它跟企业环境的差别是流程，不是责任。」
- **追问预警**：对方大概率问「出过最严重的一次事故是什么」。**必须有真实答案**，答"没出过事"反而削弱可信度（运维两年零事故 = 没有运维）。
- 千万别说：把玩家说成"用户"、服主说成"产品经理"（过度包装会被识破）。

**故事 7（技术深挖类，约 60 秒）**
> 我用原生 Canvas 2D 写了 7 款游戏，1.6 万行，没用任何引擎。代价是引擎免费给你的东西全得自己写，好处是我被迫搞懂了渲染循环和性能瓶颈在哪。我做的主要是四件事：对象池复用对象避免 GC 抖动，离屏 Canvas 预渲染静态层，事件用 16ms 节流加 200ms 防抖，DPR 自适应适配高清屏。AI 那块用了递归回溯生成迷宫、BFS 做追逐、状态机做对战。这个项目最大的收获其实是知道优化到哪一步该停——对象池容量我定 200 是实测出来的，不是拍脑袋，再加只是白占内存。

- **追问预警**：「为什么不用 Phaser / PixiJS？」是 Q3 的**同构问题**，用和 Q3 完全一样的两层结构答（当时为什么自研 / 现在会怎么选）。
- 千万别说：「引擎太重了」（与 Q3 同款减分）；只罗列优化手段不讲"为什么停在这一步"。

**Q1｜「你写了 64 个 Agent 技能、17 个 MCP 集成，怎么证明？是不是刷数量？」**

> 数量确实是我自己统计的，我不怕您质疑——这是我自己本地工作流的工具箱，不是给简历贴金的。我建议您看三个具体的：作品集里的 MCP JSON-RPC 网关是其中之一；4 个提交前安全钩子是另外四个，它们拦的是凭据泄露、硬编码、SQL 注入和翻译键缺失；剩下大部分是把重复劳动固化成脚本。真要看含金量，我更想请您看 1 个能跑通的，而不是 64 个名字。我可以现在演示 MCP 的工具调用过程。

- **为什么**：面试官测的不是数字真不真，是**你会不会吹**。本能地去捍卫数字就输了——所以主动交出数字，把战场拉到可验证的单点：能跑通的 > 报得出的。
- **千万别说**：「都是我一个个写的」（一追问就穿帮）／「不信我现场写给你看」（对抗）／逐个报名字／「这个是 AI 帮我生成的」（主动交械）。

**Q2｜「你没有实习经历，我怎么相信你能适应团队协作和代码评审？」**

> ⚠️ **重大变更（2026-09-13）：你已声明没有那段运维经历，这段已被彻底删除，原正式版话术作废。下面是新的 Q2 答法。**

> 我的项目确实都是我一个人独立完成的，这点我不包装。我能拿出的最接近协作的经历是毕设——导师定期评审、答辩委员会现场提问，我是按外部反馈改完才通过的。但要诚实讲，我没有和同事并行开发、互相 review 代码的经历。所以我最近在补：我把自己的项目开源，找人照我的 README 跑，根据他们卡住的地方改文档；我也在给用过的开源项目提 issue。我知道这是我现在最大的短板，所以我选择用能拿出链接的方式去补，而不是在简历上写一个说法。**我需要补的是规范，不是态度**——所以想问一句，你们的代码评审，是我入职后多久能参与的？

- **进阶版**（等你做完下面三个动作中的任意一个，把真实链接编进去，说服力翻倍）：
  > ……所以我最近在补：我给 [某项目] 提了一个 issue/PR（链接在这里，维护者回复了什么）；我把自己的项目开源并写了 README，找了 3 个人照着跑，他们卡住的地方我改成了 v2；我还发了一篇真实踩坑记录（HTTP 402 那次），认真回复了每条评论包括质疑的。**要不要我现在打开那个 issue 给您看？**

- **为什么**：公式 = 不否认 → 两个可验证替代证据 → 主动划出差距边界 → 用反问把劣势转成"我想学"。结尾反问是双重的：既显主动，又测试对方培养机制（若答"我们没 review"，这家公司本身就是信号）。
- ⚠️ **前置依赖**：第一段依赖"你真的对接过服主/插件作者/玩家"。**若答否，整段撤掉，改用退守版**：
  > 我确实没有企业实习，这点我不辩，我手上没有严格意义上的团队协作经历。但我能证明的是交付纪律：我一个人写 1.1 万行的毕设时没人给我 review，我就用 366 个用例给自己兜底，还上了 JWT 和 CSRF——**当我没有别人替我把关时，我会自己给自己设闸**。协作规范这块我确实要从零学，这也是我最想在第一份工作里拿到的东西，所以我想问：你们的代码评审，是我入职后多久能参与的？
- **千万别说**：「我自学能力很强所以没问题」／「实习就是打杂」／把个人项目说成"我们团队"／「我很快就上手」（又是时间承诺）。

**Q3｜「你为什么自研 ReAct 而不用 LangChain / Dify？」（全场胜负手）**

> 分两层说。第一层，当时我要的是**可控**：这个 Agent 嵌在我自己的作品集里，工具集就固定的几个，我要精确控制步数上限、单步超时、工具入参校验和答案兜底——用框架我得先学会绕开它的抽象层，反而更慢，而且出了问题我不知道往哪看。第二层，**我清楚我的自研在生产上会输在哪**：召回规模、生态集成、多人维护。所以我的判断是：这在当时是正确决策，因为它让我真正搞懂了 Agent 的循环和失败模式——坑不在模型，在循环控制。但如果进公司接的是要长期多人维护的业务系统，**我会优先用 LangChain / Dify 这类成熟方案，把自研时踩过的坑用在边界控制和降级上**。这也是我希望在这儿做的事：不是把轮子重造一遍，是把造轮子时踩过的坑用在选型上。

- **为什么**：测两件事——①你是不是只会造轮子的应届生；②你听不听得进别人的方案。所以必须答两层。**主动说出自研在生产上的劣势是核心动作**：敢说代价的人，才像做过工程决策的人。最后一句直接对接 JD 的 LangChain/Dify 要求。
- **千万别说**：「框架太重了」/「我看不上 LangChain」（傲慢且暴露没深入用过）／只讲好处不讲代价／「我试过，不太熟就自己写了」／「自己写更锻炼人」（把公司项目当练习场）。

**Q4｜「你是三本院校，基础知识可能会弱一些……」**

> 学校是普通三本，这是事实，我不辩。我理解您担心的是基础，所以我准备了可验证的东西：8 模块 12 表 88 端点的系统，是我一个人从建表写到导出脱敏的，366 个测试用例是我自己写的；Agent 那块，循环控制、超时、降级这些不是调 API 能调出来的，得自己踩过才知道坑在哪。我愿意接受任何形式的上机或笔试来证明，也更希望您在试用期用交付来验收我。

- **为什么**：不卑不亢 = 承认事实 + 立刻转向证据 + 主动提出更严格的验收方式。最后一句是翻盘点——**"敢让你考我"这个姿态本身就是反证**，基础真弱的人不敢提上机。
- **千万别说**：「三本也有厉害的人」（对抗）／「我学校不好所以我很努力」（卖惨）／抱怨高考或环境／「我基础其实挺好的」（空口自证）。

**Q5｜「你项目里说 4 万行代码，都是你写的吗？AI 帮你写了多少？」**

> 说明一下，4 万行是四个项目的加总，我先说结论：AI 生成的代码占比很高，我不回避。我的做法是——AI 出初稿，我负责三件事：定接口和边界、逐段读一遍确认没有幻觉和硬编码、跑测试。我自己写的部分主要是架构决策、推理循环、降级策略和工具网关这几块，因为这几块错了整个系统就跑不通。为了管住 AI 生成代码的风险，我写了 4 个提交前钩子，自动拦凭据泄露、硬编码、SQL 注入和翻译键缺失。如果您想验证，我可以打开提交记录，指一段给您看我当时改了什么、为什么改。

- **为什么**：这题测的是**你对 AI 使用的诚实度和掌控力**，不是比例本身。含糊过去 = 心虚；说"90% 是我写的" = 一查就穿。给出**具体分工 + 具体风控手段 + 可验证的提交记录**，把"AI 用得多"从嫌疑变成方法论。
- **千万别说**：「大部分是我写的」（可被提交记录当场证伪）／「AI 只是辅助」（回避）／一个具体比例数字（任何数字都会被追问口径）／「我改了 AI 的每一行」（不可信）。
- 💡 **配套**：准备 1 个能讲清的小例子（AI 生成了什么 → 你改了什么 → 为什么），比任何比例都有效。

**Q6｜「你投的是天津，会不会干几个月就去北京/上海？」**

> 我理解这个顾虑，天津的 AI 岗位本来就少，你们怕我拿这当跳板，这个担心是合理的。我说明两点：一是我现在住在天津、随时到岗，短期内没有任何搬迁计划。二是我选天津不是因为我只能留在天津，是因为我想做 AI 应用这个方向，而贵司这个岗位正好是这个方向——**让我留下来的是方向匹配，不只是地点**。如果我进来能完整跟一个需求从设计走到上线，我没理由在半年内换地方。

- **为什么**：发誓最没用，面试官只信动机。所以把留存锚点**从"地点"换成"成长机会"**。最后一句是软性反将：留不留得住取决于你们给不给完整交付机会——既答题，又替你争取你真正想要的东西。
- **千万别说**：「我女朋友/爸妈在天津」（外包职业决策）／「我绝对不会走」/「保证干满三年」（兑现不了的承诺）／「我没想过去外地」（与"我想做 AI"矛盾）／主动提"天津没机会我会考虑外地"（自杀式诚实）。

**反问环节 6 问**（挑 3 个问，不要全念；1、2、6 优先；技术负责人在场换进 3；一面是 HR 优先 4、5）

1. 「这个岗位第一个季度，期望我交付的东西是什么？做到什么程度算合格？」→ 测团队有没有清晰预期，答不上来多半进去是打杂救火。
2. 「现在团队的 AI 应用链路是怎么搭的？模型、编排、向量库这几层怎么选型？我进去会先接触哪一段？」→ 测真做 AI 还是蹭概念。
3. 「团队现在用 AI Coding 工具吗？有没有使用规范，允许用到什么程度？」→ **你的主场题**，最能加分；对方没想过，你就讲自己那 4 个提交前钩子，把"AI 用得多"从嫌疑变成优势。技术负责人在场必问。
4. 「应届生进来一般是谁带？代码评审多久一次？我大概多久能独立跟一个需求从需求到上线？」→ 直击"无实习"短板：你要的是 review 密度，不是放养。
5. 「这个岗位是新增的还是补缺？如果是补缺，上一位同事是什么原因离开的？」→ **听离职原因，更听回答时的犹豫程度**。
6. 「未来 6–12 个月，公司在 AI 这块是加大投入还是观望？」→ 方向稳定性；答"先看看"就不值得作为主投。

## 九之三、面试层新增纪律（2026-09-13 补充）

### 1. 被问「你做过几个项目」——不报数字，只报名字

> 「主要的有这几块：毕设的村委会业务系统、NEON CYBER 游戏平台、作品集和里面的 AI 求职助手、还有会解压的外星人。」

**为什么**：你的项目在知识库和简历里是两套口径（都算 5 个，但组成不同）。**面试官一边听 AI 助手说、一边看你的简历，就能数出来。** 报名字则：不会对不上、第 5 个项目存废都不影响、还能自然把话题引到可验证的具体项目。

这和撤掉「4 万行」是同一条原则：**不报笼统加总，只报可点开的具体项。**

### 2. 「你的项目有什么不足」——分阶段启用，别抢跑

- **gate 1 关闭前**（清库 + dist 重建没做完）：**不要用"两处维护"这条线**。因为第 1 层必须说"首页上曾留着……"，而在重建完成前它不是"曾经"、是"现在还留着"——会被当场抓。
- **gate 1 期间用这两条**（安全且真实）：① 检索层的召回上限不如专业向量库；② 自研 MCP 的维护成本高于成熟方案。
- **gate 1 之后**才启用"两处维护"那条——它更强，但不值得冒当场被抓的风险。

### 3. 演示解禁 gate（最终版）

| gate | 内容 | 状态 |
|---|---|---|
| 1 | 清库 SQL + `dist/` 重建 | ⚠️ **`dist/` 已由我在本地重建并验证；清库需你在服务器执行** |
| 2 | 三问实测全过（见〇之二） | 待你执行 |

### 4. 一道针对我们自己的闸（团队内部纪律，也对你有用）
